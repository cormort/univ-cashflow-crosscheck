# 大學現金流量表勾稽底稿產生器

上傳 `12.平衡xxxx.xlsx`（預計平衡表）與 `3.現流xxxx.xlsx`（現金流量預計表），
產生「總表 + 47 校明細」的勾稽底稿 xlsx。

## 檔案不會上傳

整支程式在瀏覽器裡用 [Pyodide](https://pyodide.org)（Python 編譯成 WebAssembly）執行。
來源檔只進到瀏覽器分頁的記憶體，**不會送到 Hugging Face 或任何伺服器**；
產出的 xlsx 也是在本機組出來後用 blob 下載。這個 Space 是純靜態網頁，沒有後端。

第一次開啟要下載約 10MB 的 Python 執行環境，之後由瀏覽器快取。實測產生一次約 6 秒。

## 兩個版本

一次產生兩份，看你要不要繼承歷年累積的調整對應：

| | 調整欄 C/D/E/F、現流代號 I | 適合 |
|---|---|---|
| **繼承版** `…-47所大學.xlsx` | 沿用範本累積的借貸代號與調整公式，依科目名稱重新錨定 | 沿用往年做法，只補新科目 |
| **空白版** `…-47所大學-空白.xlsx` | 一律留白 | 想從頭重建調整對應 |

其餘完全相同：科目、機械公式（B/G/J/L/K/M/O/P/Q）、資料區塊、逐列對齊。
兩版的 K 欄都保留——代號清空後它自然算 0，你一填代號就會自己亮起來，
而且裡面的 SUM 彙總編碼了現流的層級結構，手工重建很痛苦。

命令列預設是繼承版，加 `--blank` 產生空白版。

## 產出內容

- 年度取自來源檔標題（`中華民國NNN年…`），可在介面覆寫
- **骨架列數跟著當年度的來源走**：A 欄放平衡表縮排 ≤ 2 層的科目、H 欄放全部現流項目。
  來源沒有的科目刪列，來源多出來的補列並補上機械公式（調整欄留白待填）
- 範本累積的借貸代號（C/E/I）與調整公式（D/F）**跟著科目一起搬並重新錨定**，
  不會因為中間增刪列而指到別項。配對先做序列對齊（`機械及設備` 在撥入明細、
  撥出明細底下各有一個，只靠名字會配錯），落單的再按名字補配；順序以骨架為準
  （`什項負債` 排在 `遞延負債` 前面是刻意的，重排會拆散它底下整組調整列）
- 47 張明細表與總表**逐列對齊**，總表跨表加總一律指同一列，整欄公式可直接往下拉
- **借貸代號依艾富公版重新編號**，格式 `活動別1碼 + 群2碼 + 序2碼`（如 `10401` =
  業務活動／折舊、減損及折耗／土地改良物）。舊制對著「當年度的清單」編號，某年缺一項
  後面就整組位移——實測 113→114 就這樣改動了 30 個代號。現在對著公版（所有年度的
  完整超集）編，槽位固定，缺項不位移。舊代號留在 V 欄對照，下一年度可移除
- **總表 T／U 欄逐列列出「哪幾所學校不一致」**。總表的 `K1 = L1+2` 而 `L1=0`，
  指到資料區塊的合計欄，所以總表的 M/P 看到的是 47 校**加總**後的差異——
  甲校 +100、乙校 −100 會互相抵消顯示 0，個別學校的不一致就藏起來了。
  T 欄列出該列 `M≠0` 的學校、U 欄列出 `J≠K` 的學校
- **差異標色（條件式格式）跟著骨架長度走**：`J≠K`（現流數對不上由調整反算的數）與
  `M≠0`（平衡表數對不上調整推出來的數）就是勾稽的視覺呈現。範本 47 張表原本有 12 種
  形狀——J 欄裂成 2~4 段、19 條規則比對 `#REF!`（死規則）、M 欄在 M94:M96 破洞、
  結尾停在 134~136 列。現在統一成一組並蓋滿整個骨架
- 五份原始資料只寫一份在總表底下，明細表用 VLOOKUP／OFFSET 指過去

工作表一律**認結構不認名字**（表名逐年是 `細修0814`／`細`／`明細`／`Sheet1`）：
平衡表看 A1 的 `1.本年預算數`／`5.上年調整後預算數`，現流看第 4 列有沒有 47 個校名。

## 檔案

| 檔案 | 說明 |
|---|---|
| `index.html` | 網頁介面（Pyodide，無後端） |
| `build_gouji.py` | 產生邏輯；瀏覽器與命令列共用 |
| `template.xlsx` + `.mirror.json` | 骨架範本，**已清掉所有年度金額**，只留科目名稱 |
| `現流代號主檔.json` | 由艾富公版產生：現流項目 → 代號。公版換版時用 `--master` 重跑 |
| `勾稽配對表.json` | 累積的專業判斷：平衡表科目調整 → 對應的現流項目。**這份是人工資產** |
| `勾稽規則.md` | **底稿本身的規則**：表怎麼運作、代號怎麼編、來源怎麼認、既有缺陷、如何擴充配對表 |
| `extract_pairs.py` | 從別的勾稽表抽配對並評估覆蓋率（只讀不改） |
| `test_build.py` | 靜態檢查：查表公式指到的列名稱是否相符、骨架清單是否等於來源、逐列對齊 |
| `test_recalc.py` | 重算檢查：用 LibreOffice 真的算一遍，看有沒有錯誤值、檢查欄算不算得對、平衡列平不平 |

## 部署

純靜態網站，兩邊都可以，檔案內容完全一樣。

**GitHub Pages**：把 `index.html`、`build_gouji.py`、`template.xlsx`、
`template.xlsx.mirror.json`、`.nojekyll` 推到 repo，
Settings → Pages → Source 選該分支的根目錄即可。
`.nojekyll` 一定要有，否則 Jekyll 會插手處理靜態檔。
子路徑（`https://<帳號>.github.io/<repo>/`）已實測可用。

**Hugging Face Space**：建 Space、SDK 選 **Static**，把上表檔案（含 `README.md`）推上去。

`template.xlsx` 約 1.1MB，兩邊都不需要 git-lfs。

> 注意：GitHub Pages 一律是公開的（即使 repo 是 private）。
> 這裡沒有敏感內容——範本已清空金額，來源檔也從不離開瀏覽器——但網址等於公開。
> 想限制存取就用 HF Space 的 Private。

## 命令列用法

```bash
pip install openpyxl
python build_gouji.py 12.平衡0814.xlsx 3.現流0814.xlsx            # 繼承版
python build_gouji.py 12.平衡0814.xlsx 3.現流0814.xlsx --blank    # 空白版
python test_build.py  大學115現金流量表勾稽檔-47所大學.xlsx 12.平衡0814.xlsx 3.現流0814.xlsx
python test_recalc.py 大學115現金流量表勾稽檔-47所大學.xlsx
```

**改完程式兩支都要跑。** 兩支查的東西不重疊：

`test_build.py` 是靜態的，不需要參考檔——骨架列數會跟著來源變，拿舊年度的勾稽檔逐格比已經沒意義。
它改查產出自己該成立的性質：每條 OFFSET／VLOOKUP 指到的那一列，科目名必須就是這一列自己的科目名。

`test_recalc.py` 用 LibreOffice 真的算一遍再讀回結果。靜態檢查抓不到「公式長得對、算起來錯」——
總表的骨架比明細樣板低一列，曾經因此整張總表的參照多位移一列，`test_build.py` 全綠，重算才噴 `#VALUE!`。
它查四項：無錯誤值、`M=L-G`、`P=J-K`、以及底稿自帶的平衡列。
其中**上年平衡列（B 欄）必須 47 校全為 0**，那是純從來源查表得到的數，不平衡就代表資料沒正確搬進去；
本年平衡列（G 欄）只報數不判定，調整分錄本來就要人工填完才會歸零。

沒裝 LibreOffice 的話 `test_recalc.py` 會整支跳過（exit 0）：

```bash
brew install --cask libreoffice
```

用別的勾稽表擴充配對表（只讀不改，會報告名稱重疊率與能補的缺口）：

```bash
python extract_pairs.py 別人的勾稽表.xlsx [輸出.csv]
```

從新的歷年勾稽檔重做範本：

```bash
python build_gouji.py x y -t 大學NNN現金流量表勾稽檔-47所大學.xlsx --strip-template template.xlsx
```
